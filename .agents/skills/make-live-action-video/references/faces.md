# 顔の検出・丸ぼかし・再利用

## 検出と見た目は別

顔検出結果をフレーム番号付きJSONLとして保存し、ぼかしの形・強度を変えても検出を再実行しない。
ただし、入力映像・クロップ・回転・速度・fps・座標系・検出設定が変われば別traceにする。
`video/scripts/hybrid/faces.py`の既定はYuNet単独・矩形・過去0.25秒保持であり、#289で採用した丸ぼかしそのものではない。直接実行して完成扱いにしない。

## 街歩きの候補検出

以下は#289で試作を経て採用した構成。モデルの入手元・ライセンス・バージョン・hashを確認し、短い試作で必要な検出器を選ぶ。モデル本体はスキルに同梱しない。

1. 全フレームをYuNet（1280px幅、候補閾値0.45）で検出する。`hybrid.faces.ensure_model`のchecksum付き取得とライセンスを再利用可能。
2. macOSではApple Visionの顔矩形検出も全フレームで実行し、横顔・別方向の候補を補完する。Visionの下原点座標は`y = 1 - maxY`で上原点へ変換する。入力の回転を反映する。
3. 群衆・遠景・遮蔽が多い場合は人物poseを補助にする。#289はYOLO26n-poseを4フレーム間隔、全体＋重なりのある下部4タイルで使用。元4Kの下部1280pxタイルはその解像度専用の例であり、他の寸法では再計算する。
4. 目・耳・鼻・肩から頭部候補を作り、重複した人物領域を抑制。近傍のサイズ・距離が妥当な候補だけを一対一対応させて補間し、短い未対応区間は両側の領域を保持する。
5. 各フレームの顔候補に±2フレームの近傍候補とpose頭部を補足する。#289では0.9未満の顔候補は独立した人物領域との交差が顔面積の20%以上ある場合に採用し、看板の誤検出を減らした。補助人物が失敗している区間ではこの閾値で小さい顔を黙って捨てず、試作を確認して調整する。
6. 拡張済みの矩形と、当該フレームで採用した顔の元矩形を別々に記録する。#289は顔の30%拡張、poseの18%＋4px拡張を基準にした。群衆を一つの大きな矩形へまとめない。

実装を再利用する場合、[episode-289.md](episode-289.md)に実証コードの場所がある。これは参考であり、ファイルがなくても上の契約と現環境の検出器からtraceを作れる。話数固定のパスや部分完了のファイルを実行前に汎用化する。

## 同梱レンダラーの入力契約

映像は時計・構図が確定したSDR BT.709・CFR・開始PTS=0。traceはその映像の**全フレーム**を0から順に1行ずつ持つ。

```json
{"frame":0,"boxes":[[100,150,180,240]],"acceptedFaceCores":[[115,170,165,220]]}
```

`boxes`は拡張済みマスク、`acceptedFaceCores`は検出した顔そのもの。両方とも出力座標で`[x1,y1,x2,y2]`、上原点。未検出は両配列を空にして記録する。
既存pipelineの`.faces.jsonl`はこの契約と同一ではない。単にファイル名を替えず、実際に使う拡張・補間・手動マスクを含むtraceへ変換する。

別途manifestを作る。sourceとtraceのSHA-256を、各検出器が実際に読んだ映像に結び付ける。異なる入力のtraceを正当化するためにhashだけを後付けしない。

```json
{"sourceSha256":"SOURCE_SHA256","traceSha256":"TRACE_SHA256","frames":2400,"fps":"24000/1001","width":1920,"height":1080,"state":"ready"}
```

```sh
uv run SKILL_DIR/scripts/round_faces.py camera.mp4 masks.jsonl masks-manifest.json preview.mp4 --first 1200 --frames 720
uv run SKILL_DIR/scripts/round_faces.py camera.mp4 masks.jsonl masks-manifest.json round-clean.mp4
```

出力は無音。プレビューには同じマスター時刻の音声と固定テロップを合成して見せる。`--dry-run`も入力検証を行うが書き出さない。
既定は拡張矩形に対して幅・高さ85%、外周22%のsmoothstepフェザー、Gaussian sigmaは短辺の9.5%（最低2.2px）、中央不透明。
小さくした結果、目・口に相当する中央3点が内側78%を外れる顔には補助楕円を追加する。これは識別不能を保証する検査ではない。
`--scale`は大きさ、`--sigma`はぼかし強度、`--roundness`は0が元の楕円・1が長い半径に合わせた真円、`--feather`は外周のなじませ幅（既定0.22）。「もっと丸く」はscaleだけでなくroundnessで調整し、形の変更後も中央点の保護を検査する。

単純に全体のopacityを落とすと元の顔が戻る。弱めるときはぼかし強度・範囲・外周を調整し、顔が読み取れないか確認する。
ツールは新しいファイルに`.pending.mp4`を書き、成功後に完成名へ変更する。途中停止時は旧版・途中ファイルを保管し、新しい版名で再開する。
長尺は独立した区間を少数並列に処理できる。1フレームでも境界がずれたら全編を使わず、PTS、境界直前直後の元映像との照合、連結後のフレーム数を確認する。部分出力の`ready`は全編完了ではない。

## 確認の範囲

近い顔、遠景の小さい横顔、人の交差、画面端、窓への映り込み、暗所、カメラの急旋回をサンプルに選ぶ。
ゼロ件検出は「人がいない」の証明ではない。検出漏れ・余分なマスクを区間ごとに記録し、追加マスクまたはResolveで修正する。
全フレームへの処理、検出された顔の中央点の被覆、代表場面の目視、人間による全編視聴は別の検査として記録する。
