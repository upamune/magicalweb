# Resolve組み立て・最終検査

## 接続と復旧

実際の起動プロジェクト・タイムライン・レンダー中かを読んでから操作する。別プロジェクトを思い込みで変更しない。
外部スクリプティングが既に許可されていればインストール済みAPIを使う。許可されていなければネイティブのWorkspace→ConsoleからLuaを実行できる。
UIは利用可能なcomputer-useツールを使い、操作後の状態から要素を再取得する。固定AX番号を保存しない。
外部スクリプティングを有効化するためのセキュリティ設定変更は勝手に行わない。
Macロック中は実操作が失敗しうる。設定を迂回せず、必要な解除をユーザーへ伝え、独立したローカル処理のみ続ける。

## タイムライン

- fpsは有理数で制作manifestに保持する。UIの23.976は`24000/1001`として扱う。24fps固定の既存pipelineへそのまま流さない。
- 全工程で区間を`[start,end)`に統一する。境界をフレームへ量子化する方法を一度決め、Classic・実写・テロップ・source trimで共通にする。
- Resolve 21の#289実機では`AppendToTimeline`の`endFrame`は排他的だった。別バージョンは短いクリップで実長を確認し、常に追加後の`GetStart()/GetEnd()`を検査する。
- RenderSettingsの`MarkOut`は包含終端なので、Nフレームなら`MarkIn=start`、`MarkOut=start+N-1`。
- 無効トラック上の古いクリップが長いと全体尺を延ばす。`SelectAllFrames=false`で意図した範囲を明示する。
- タイムラインを複製・切り替えた直後はUIの切り替わりを待ってから有効状態を読む。#289では非アクティブtimelineのtrack enable取得が現在のtimelineを反映する挙動があった。

一般的な構成は、Classic用V、実写用V、その上に透過テロップ用V、マスター専用A。
トラック番号を#289からコピーせず、現在の構成から取得して記録する。
元マイク、カメラ音声、古い字幕やデザインを無効にし、マスターが一度だけ鳴ることを確認する。

修正時は元を複製し、変更するクリップの名前・開始・終端をassertしてから、そのコピーの対象だけ置換する。
置換前後で、変更対象外のクリップ・範囲・有効状態を照合する。
前半と末尾も含め各素材のhashを保持する。DRPはメディアを内包しないためパスを維持する。

## 色・透過・書き出し

#289はrawカメラがBT.709、Classic生成物がfull-range/BT.601タグで混在していた。
RGB処理した実写をYUVに戻す場合、タグを付けるだけでなく`scale=out_color_matrix=bt709:out_range=tv`等で数値を正しく変換する。
静止画や素材の見た目だけで判断せず、Resolveの短いH.264出力の黒・肌・字幕色で確認する。HDRは別途色管理を決めてから処理する。
透過テロップはStraight/Premultipliedの取り違えで縁や色が変わる。合成後の字幕を確認する。

APIではプリセットを読み込んでから今回の出力設定で上書きする。
1080p H.264の出発点は16Mbps、AACステレオ48kHz。設定の選択タブが「Audioでない」ことと、ExportAudio=falseを混同しない。
新しい版名を使い、書き出し先が存在していたら上書きせず照合または別名にする。

1. 短いプレビューを追加し、今回作ったジョブIDだけ`StartRendering({jobId})`する。
2. 実ファイルの映像とマスターとの音声同期を確認する。
3. 明示した全編範囲のジョブを追加し、プロジェクト保存と別名DRP出力後に、そのジョブだけ開始する。
4. `IsRenderingInProgress()`だけで成功を判断しない。該当ジョブの100%・成功状態（日本語UIでは「完了」）と出力ファイルを検査する。

## 完成ファイルの検査

```sh
node SKILL_DIR/scripts/verify_delivery.mjs \
  --file /absolute/final.mp4 --master /absolute/master.wav \
  --fps 24000/1001 --frames 62434 --require-resolve \
  --sample-frames 0,31471,31472,38208,62309,62310,62433 \
  --drp /absolute/final.drp --report-dir /absolute/new-verification-folder
```

数値は#289の例。新しい回ではmanifestから指定し、新規report-dirを使う。
既定検査は1920×1080、指定fps/フレーム数/尺、音声2ch/48kHz、LUFS−16±0.5、TP≤−1。
音声はマスター全尺が対応する前提で、既定5地点を8kHzモノラル相関で照合する。
部分プレビューは`--master-offset SECONDS`を付け、`--sync-times 7,22`などを指定する。
映像境界は整数フレームで指定し、最終フレームも加える。音声AACのパディングは映像尺とは区別する。
DRPを指定した場合は`unzip -t`の整合性とhashも記録する。

`--require-resolve`はResolveのencoderタグも検査する。FFmpeg合成による確認用をResolveネイティブ出力と呼ばない。
ヘルパーが出す`passed-automated-checks`は機械検査のみ。PNGを開いて、レイアウト・二重字幕・顔ぼかし・両方の切り替えを確認した後、制作状態を`verified-local-render`にする。
黒画面検出は99%以上が黒い状態の0.04秒以上の区間を報告する。意図した暗転なら理由を確認して記録し、問題を隠すため閾値を緩めない。
意図した暗転の確認が伝えられた場合だけ、`--black-review /absolute/review.json`で例外を渡せる。JSONは`videoSha256`、`reviewedBy`、`intervals:[{start,end,reason}]`を持ち、検出された全区間の開始・終端と動画hashに対応させる。別版や未確認の暗転に流用しない。これで音声・DRP等の残りの検査も実施できるが、全編プライバシー確認の代わりにはならない。

## 再開と中断

素材は内容hash別に保持する。途中ファイル、部分処理、ジョブに登録されただけの出力を完成品として再利用しない。
実行中のスクリプト・モデル・入力は凍結する。変更するなら現在の処理を特定して止め、別版として再実行する。
終了するのは今回起動した子プロセスだけ。マシン全体のChromeやffmpegを一括終了しない。
保存済みDRP、MP4、素材と検査結果の対応を制作記録へ残す。投稿やクラウド保存はこの工程に含まない。
