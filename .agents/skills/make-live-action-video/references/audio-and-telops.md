# 同期・音声・テロップ

## 生素材とマスター時計

- 原本は読取専用として扱い、probe結果、録音順、話者、hashを制作記録へ保存する。`mic1`を特定の話者と決めつけない。
- 分割音声はBWF・サンプル数・実録音の連続性を確認する。ファイルのコピー日時は同期根拠にならない。停止・再開による空白を無音として保持し、浮動小数音声を音量調整前に整数化しない。
- 連結後はRIFFのサイズ、dataチャンクの宣言サイズ、実バイト数・サンプル数を照合する。2026-09-21にローカル`hollyland-audio`の`concat_wav_parts`で、既にバイト数の`total`を4倍してヘッダーへ渡していた箇所を`_wav_header(total, 1)`へ修正した。別環境・古いコピーでは同梱テストで確認してから使用する。4GBを超える場合は通常RIFFの上限を超えるためRF64対応の別経路が必要。
- Hollylandの分離が強い2本は、まず共有低域30〜140Hzを使う`hollyland-audio`の手順を試す。過去の5〜12msという値や周期的な相関ピークを次の回の正解にしない。独立した区間で残差を検証する。
- マスター長は採用範囲の和集合。早い側の冒頭・遅い側の末尾を勝手に落とさない。ユーザーの編集指定があれば、編集後をマスター時計として確定する。

カメラの対応は`masterSeconds = offsetSeconds + scale × sourceSeconds`。
番組checkoutの`video/scripts/hybrid/audio.py`にある`features` / `estimate_sync`はカメラ音声との複数点照合に再利用できる。使う前に現在の関数と前提を読む。
マスター上の離れた3点以上で検証し、残差・ドリフト・先頭末尾の範囲を記録する。共有音が不足する場合は手動アンカーを確認し、無根拠にscale=1へ落とさない。
ドリフト補正、回転、クロップ、fps変換は顔検出より先に確定する。変えたら検出の時計と座標も変わる。
最終音声はマスター1本だけ。カメラ内蔵音声は照合用であり二重に混ぜない。

## 雑音とラウドネス

1. Resolve/Fairlightで会話レベル、かぶり、交通音を確認する。#289のVoice Isolation=65、75Hzハイパスは出発点であり固定値ではない。子音が欠ける、水中のような音、ポンピングが出るなら弱める。
2. 交通音が強い箇所だけ調整し、無音ゲートで語尾や相づちを切らない。雑音をゼロにするために会話を壊さない。
3. 処理済みの会話をWAVへ出力し、目標が従来どおりなら同梱ヘルパーを使う。

```sh
uv run SKILL_DIR/scripts/master_audio.py cleaned.wav master.wav --highpass 75
```

標準は2パスで−16 LUFS、処理段階TP−1.5dBTP、48kHz/24bitステレオ。
既にハイパス処理済みなら`--highpass 0`。新しい出力パスを指定する。`--dry-run`は書き出さない。
最終AACは別途測定し、−16±0.5 LUFS、TP≤−1dBTPを目安にする。#289の実測値を新作の測定値として報告しない。

## 文字起こしをテロップにする

番組用には`make-episode-video`と`video/scripts/build-episode.mjs`の校正・固有名詞置換・ページ化を再利用する。
`hybrid_pipeline.py`の既定Whisperは選択肢の一つ。#289はScribe v2を採用したが、次回も実音声の難しい数十秒で話者・固有名詞・切れ目を比べる。根拠なしに「今のほうが高精度」と決めない。
クラウド認識／校正は音声／発話内容の外部送信になる。ローカルの未公開素材について、サービスと送る内容がユーザーの承認範囲にあるか確認する。既存APIキーや前回の承認だけで新しい素材の送信を推定しない。ログにキーを出さない。

### クラウド禁止の場合

ローカルWhisper等で認識し、ローカル処理で校正したtranscriptを使う。モデル取得が必要な場合は、モデルのダウンロードと音声の送信を区別して説明する。
素材や発話内容をクラウドへ送らない指定は、外部文字起こしAPIだけでなく、このチャットや外部LLMへ本文・音声・画像を渡すことにも適用する。ローカルツール内で処理し、進捗・検査数値・必要なメタデータだけを確認する。見た目や試聴はユーザーにローカルで確認してもらい、その確認範囲を記録する。送信禁止の範囲が曖昧なら、送信前に確認する。
現行`build-episode.mjs`は`--no-proofread`だけでは話者判定を止めない。自己紹介で確認した全ラベルの`--speakers`を**併用**し、音声もローカルの`--audio`で渡す。
さらに現行実装は空の認識語があると`--no-proofread`でも校正キューに戻してしまう。**ローカル専用の作業コピー**で、`const pending = segments.filter((s) => !proofread[s.id]);`を`const pending = noProofread ? [] : segments.filter((s) => !proofread[s.id]);`へ変更してから以下を実行する。元checkoutの作業中コードには触らない。
空の認識語を含むテストで`fetch`呼び出し回数が0であることを確認する。通信エラーを投げるだけでは呼び出し側に握りつぶされるため、「通信に失敗した」と「呼び出さなかった」を区別する。同梱のローカルbuildテストを参照する。

```sh
bun scripts/build-episode.mjs 290 --transcript /absolute/local-transcript.json \
  --audio /absolute/master-preview.mp3 --episode-meta /absolute/episode-meta.json \
  --no-proofread --speakers A=michiru,B=upamune
```

ラベルA/Bと人物の対応は例。`--no-proofread`は入力wordsからページを作るため、ローカル校正はその入力へ反映する。
Ollamaがlocalhostでも`:cloud`モデルなら外部送信される。ローカルモデルを使う場合も実際のモデルとendpointを確認する。
自動話者判定・校正・音声の自動ダウンロードの全経路を確認し、クラウド禁止のまま止まる場合はローカル作業を続けて不足を伝える。黙ってScribeへ切り替えない。

### 逐語文字起こしから画面用テロップへ

文字起こしは検索・校正・同期のための中間素材であり、そのまま画面へ出す完成品ではない。認識誤りを直す校正と、読ませる量・文体を整えるテロップ編集を別工程として扱う。

1. 校正済みtranscriptを作る。固有名詞、話者、語順、開始・終了時刻を音声と合わせる。
2. 発話ごとに意味の核を決め、フィラー、短すぎる相づち、言い直し重複を整理する。言っていない結論やニュアンスは足さない。
3. 1ページ1つの意味のまとまりにし、助詞だけを次ページへ残さない。1行22文字・最大2行を出発点に、語のまとまりで改行する。
4. テロップの開始は、削除したフィラーではなく最初に残した意味語へ寄せる。話者、発話順、終了時刻を別の発話へ移さない。
5. 冒頭、通常会話、早口、言い直し、リアクション、実写の切り替え前後をプレビューし、「耳で聞けば分かるが画面では冗長」な逐語字幕が残っていないか確認する。

会話系の実写テロップでは、次を既定の編集方針にする。番組固有の表記やユーザー指定があればそちらを優先する。

- 文末の`。`と途中の`、`を基本的に表示しない。`？`と`！`は疑問・驚き・強調を伝える場合に残す。句読点を消した結果、語の境界が読みにくければページ分割や改行で解決する。
- 単独の「あ」「えー」「えっと」「お」「うん」「はい」「まあ」などは、意味や反応を担わなければ削除する。掛け合い、同意、否定、間の面白さに必要な短い反応は残す。
- 文頭の「あの」「その」「なんか」なども、単なる発話開始の癖なら削除する。一方で「なんかありそう」の`なんか`のように意味を持つ語まで一括削除しない。
- 直後に具体化した言い直しは重複を畳む。例: `おじさんに、海外のおじさんに撮られた` → `海外のおじさんに撮られた`。迷い自体が笑いや意味になる箇所は残す。
- `っていう感じ` → `って感じ`のような縮約は、意味・温度感・話者らしさが変わらない範囲だけにする。話し言葉を説明文や整いすぎた書き言葉へ変えない。
- 認識不能な断片や不自然な固有名詞は、推測で滑らかな文にしない。音声を試聴して直すか、意味が成立しなければ非表示にする。
- 異なる話者や離れた時刻の発話を、読みやすさのために一つへ合成しない。テロップを短くしても、映像と音声の発話位置は保つ。

機械検査では、ページ時刻の昇順・非重複、最大行数・文字数、空ページ、禁止した句読点、フィラーだけのページ、同一文の近接重複を調べる。機械検査だけで自然さは保証しないため、変更前後の代表例を制作記録へ残し、実際の映像へ重ねて読む。

完了報告には、元ページ数、完成ページ数、フィラーだけで除外したページ数、変更したページ数、保持した例外方針を記録する。文字起こしファイルの生成完了を、テロップ編集完了として報告しない。

- 自己紹介などで話者を確認。同時発話を単純なマイク音量だけで断定しない。
- マヂカル.fm、みちるだ等の番組固有語を全文で確認する。番組横断で妥当な置換と、その回だけの修正を分ける。
- 未公開回は`build-episode.mjs`の実装で`--episode-meta`と`--no-proofread`を確認する。現行helpには両方が表示されない。RSSに別回を追加して代用しない。

タイトル未定なら、タイトルに依存しない処理を進めながら表示名を確認する。確認用に「第N回（タイトル未定）」等を使う場合は仮表示だと伝え、確定名として公開しない。
現行metadataは`number`、文字列`title`、文字列`pubDate`が必要。表示日が未定なら作業用metadataの`pubDate`を空文字列にし、画面でも空欄にする。録音日を公開日として捏造しない。
最終版では確定表示を確認するか、ユーザーが仮表示での納品を指定したことを記録する。

完了時、transcript、話者対応、校正キャッシュ、ページ化propsを同じマスターのhashに結び付ける。尺を変更したら字幕と映像の時刻を再計算する。

## Classicと固定透過テロップ

### 24以外のfps

現行`build-episode.mjs`の`FPS=24`はpropsだけでなく音量エンベロープの時間刻みにも使われる。
24以外なら作業用コピーでこの定数を選んだ有理数（例:`30000 / 1001`）へ変更してからbuildし直す。
同じコピーの出力`durationSec: round(durationSec)`を非丸めの`durationSec`へ変更し、`ceil(durationSec * FPS)`で求める総フレーム数がエンベロープ長・Composition・rendererで一致することを確認する。
`Root.tsx`はpropsからfpsと尺を計算していることを現物で確認し、独自の透過Compositionも同じ値を参照させる。秒単位の字幕時刻は維持し、実写境界・透過素材・Resolveの配置をそのfpsで一度だけ量子化する。
fpsだけを出力エンコード時に変更したり、生成済みpropsのfpsだけを書き替えて24Hzのエンベロープを残したりしない。

実装の参照先は`video/src/episode/ClassicEpisodeView.tsx`、`EpisodeCaption.tsx`、`EpisodeSpeakerBar.tsx`、`StreetVideoView.tsx`。
Classicのカラオケと、実写用の固定テロップは別扱いにする。透過専用Compositionがなければ作業用コピーで既存字幕コンポーネントを使うものを用意する。
フォントのロード完了を待ち、代替フォントで全編を生成しない。

固定テロップはページごとに透過PNGを1回描画して、そのページのフレーム数だけ保持できる。
各フレーム`n / fps`で`page.start <= t < page.end`を評価し、連続する同じページをまとめる。字幕のない区間も透明フレームとして保持する。
長いページの先頭・中央・末尾を別々にレンダーし、画像hashが一致することを確認してから静止画の再利用へ進む。

出力はProRes4444等の透過を保持する形式。concat入力の静止画にも正しい有理数fpsを明記する。
#289の23.976では`option framerate 24000/1001`と`fps=24000/1001:round=near:eof_action=pass`を使用。`-r`だけで補正したつもりにならず、切り替え前後の画像と総フレーム数を検査する。
ResolveではStraight alphaを短い書き出しで確認する。全編の透過素材は非常に大きくなりうるため空き容量を先に調べる。
