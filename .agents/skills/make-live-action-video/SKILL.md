# 実写ビデオポッドキャスト制作

完成音声を唯一のマスター時計にし、映像がある区間だけ実写にする。
完成品はローカルMP4と編集用DRP。素材処理済みと最終書き出し済みを区別する。
これは工程を進めるスキルであり、全工程を無条件に実行する単一CLIではない。

## 開始・再開

1. 指定された素材フォルダ、話数、タイトル、使用範囲を確認する。決まっている情報は再質問しない。
2. 既存の制作記録・状態JSON・完成品・Resolveのタイムラインを調べ、最後に検証済みの工程から再開する。顔ぼかしだけの変更なら音声・文字起こし・前半を再生成しない。
3. `ffprobe`で実素材の音声形式、動画の寸法、回転、色、開始PTS、有理数fps、フレーム数を調べる。複数カメラ、VFR、HDR、録音の停止・再開を先に識別する。
4. 素材フォルダの`out/`に作業用コピー・版別成果物を置く。`magicalweb`の作業中データを上書きしない。空き容量は完成品だけでなく、透過素材・分割出力・結合途中の同時保持まで見積もる。

番組実装はこのリポジトリの`video/`。話数固有の生成では、素材フォルダの`out/episode-style/`などへ制作コピーを作り、追跡中の番組データを直接上書きしない。
別checkoutで使う場合はリポジトリルートを特定する。別の番組ならデザインを流用する前に対象を確定する。
Pythonの同梱ヘルパーは`uv run`、検査ヘルパーは`node`で動く。`ffmpeg`と`ffprobe`が必要。
資料内の`SKILL_DIR`はこの`SKILL.md`の親ディレクトリの絶対パスに置き換える。

## 今回からの既定値

ユーザーの新しい指定を優先し、以下は出発点として使う。

| 項目 | 既定 |
| --- | --- |
| 画面 | 1920×1080。fpsは素材と既存タイムラインから決定し、23.976と24を混同しない |
| 前半・映像のない隙間 | `make-episode-video`のClassic画面。従来のカラオケ強調を維持 |
| 実写テロップ | PR #11由来の話者別ピンク／水色、けいふぉんと！、白縁・細い黒フチ1px・影、左に話者アイコン、最大2行 |
| テロップ文体 | 逐語録をそのまま表示しない。句読点・フィラー・言い直しを画面向けに整理し、意味・話者らしさ・疑問／強調は残す |
| 実写の文字の動き | ページ内は完全固定。読み上げ追従の上下移動・単語強調なし |
| 顔ぼかし | 小さめの楕円ガウスぼかし、柔らかい外周。中央は100%処理。具体値は顔ぼかし資料 |
| 音声 | ステレオ48kHz、目標−16 LUFS、最終AACのTrue Peak≤−1 dBTP |

## 工程と完了条件

### 1. 同期・音声・テロップ

[references/audio-and-telops.md](references/audio-and-telops.md)を読む。
Hollylandの分割WAVは、利用可能なら`hollyland-audio`のSKILL.mdと必要な資料を読んで連結・同期する。
マイク対応は自己紹介や試聴で確認する。各カメラをマスター時計へ対応付ける。
Resolveで会話を整え、必要なら同梱`master_audio.py`で2パス音量調整する。
文字起こしは入力音声と対応したものを使う。認識誤りの校正後に、逐語録から画面用テロップへの編集パスを独立して行い、それからページ化する。ASRの誤変換が直っただけではテロップ完成とみなさない。

完了条件: 同期の複数アンカーと残差、音量実測、話者対応、テロップ編集の方針と変更数、字幕ページ、フレーム境界が記録されている。フィラーだけのページ、句読点だらけの逐語字幕、意味のない言い直し重複が残っていないことを代表区間で確認する。
同期値・話者・日時を#289からコピーしない。

### 2. 顔検出と短いプレビュー

[references/faces.md](references/faces.md)を読む。検出と見た目の適用を別工程にし、検出結果を再利用する。
丸ぼかしの実装は`scripts/round_faces.py`。顔検出器ではなく、全フレームのマスク記録を焼き込むヘルパー。
群衆・横顔・遠景・窓の反射を含む区間で、テロップと音声を合成した20〜30秒のプレビューを作る。
既に承認されたスタイルは引き継ぐ。新しいスタイルや素材で目立つ差があれば、比較を見せて確認する。

完了条件: 入力と検出記録の対応が確認でき、短い映像で位置・追従・強さ・字幕の読みやすさが確認できる。
見た目の承認は全編のプライバシーレビューではない。

### 3. 素材生成・Resolve組み立て

[references/resolve-and-delivery.md](references/resolve-and-delivery.md)を読む。
既存`davinci-resolve`スキルはAPI操作の補助に使う。既存`make-episode-video`スキルは文字起こし・Classic生成を再利用する。
各スキルの無条件のコミット、全プロセス終了、セキュリティ設定変更を引き継がず、この依頼の対象だけを扱う。

前半・末尾、実写映像、固定の透過テロップ、マスター音声を別々に用意する。
入力・props・コード・モデル・設定のハッシュが一致する検証済み素材だけを再利用する。
修正時は新タイムラインへ複製し、対象トラックだけ差し替える。

完了条件: 区間と音声長、全トラックの有効状態、素材fps・色・透過方式を検査し、Resolveからの短い書き出しも確認済み。

### 4. 全編書き出しと検査

正確なフレーム範囲で今回のレンダージョブだけ開始する。ジョブ完了、実ファイル、保存済みプロジェクト、DRPを確認する。
同梱`scripts/verify_delivery.mjs`で形式・LUFS・ピーク・音声照合・全編デコード・黒画面を検査する。
検査用に抽出したフレームを実際に開く。前半、実写への切り替えの直前直後、群衆、両話者・2行字幕、末尾への切り替え、最終フレームを含める。

完了条件: 実ファイルの検査が通り、代表フレームの目視確認とDRPの整合性が記録されている。
「検出済みの顔を覆った」「15枚を見た」を「全員の顔が確実に匿名化された」と報告しない。

## 状態・引き渡し

工程状態は`inputs-checked → synced → master-ready → captions-ready → preview-approved → assets-ready → resolve-rendering → render-complete → verified-local-render`を目安に、対象ファイル・ハッシュ・処理範囲・ジョブIDとともに記録する。必要な工程がない修正は省略できる。
`privacyReview`は別フィールドで管理し、人間が全使用区間を確認するまで`pending-human-review`を保つ。
`prepare-episode-video.mjs --reviewed`はその確認が伝えられた素材にだけ使う。ローカル確認用を作るためにレビュー済みreceiptを偽造しない。

長い処理は進捗と出力を確認して最後まで進める。Macロックや未承認の外部送信など、権限が必要な境界では具体的な必要操作を伝える。ローカル素材処理は続行可能なら進める。
外部公開・アップロード・コミット・pushは別依頼として扱う。
最終回答には**最新版の絶対パスの動画リンク**、DRPリンク、実測音量、残る確認を簡潔に示す。旧版は保持する。DRPに素材本体は入っていないことを制作記録へ残す。
