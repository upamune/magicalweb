# make-live-short: 実写回の縦型ショート

完成した実写回（`make-live-action-video` で作ったもの）から、見どころを30〜55秒に詰めた縦型ショートを作る。
映像は顔ぼかし済みの素材、音声は完成版の音声を使い、字幕と見出しは縦型用に作り直す。
見た目は `video/src/short/LiveShort.tsx`（Composition `LiveShort`）、素材の切り出しと書き出しはこのスキルの `scripts/` が受け持つ。
流れは「台本 → 検査 → 試し書き出し → 通しの見直し → 本番の書き出し → 検査」。考え方は [kokushin/short-animation-harness](https://github.com/kokushin/short-animation-harness) を参考にした。
資料内の `SKILL_DIR` はこの `SKILL.md` の親ディレクトリの絶対パスに置き換える。

## 前提

- 本編ごとに次の3つが揃っていること。モロッコ編の所在は [references/morocco-290-292.md](references/morocco-290-292.md)
  - **完成MP4**: 音声をここから取る。本編の時刻（編集後の秒）の基準
  - **顔ぼかし済み・字幕なしの映像**: 本編の0秒が何フレーム目か（`offset`）を確認しておく
  - **ElevenLabs Scribe の生JSON**: 本編と同じ時計のもの
- `ffmpeg`、`uv`、`bun`（Remotion は `video/` の依存を使う）
- 素材が外付けSSDにあるときは、切り出した結果だけを内蔵の作業フォルダへ置く（数百MB程度）

## 手順

### 1. 作業フォルダと parts.json

`~/src/tries/<日付>-<名前>-shorts/` のように内蔵ディスクに作り、`parts.json` に本編ごとの素材を書く:

```json
{
 "002": {"offset": 36, "mosaic": ".../vlog-002.mosaic.mp4", "final": ".../magicalfm-291-morocco-002.mp4",
         "transcript": ".../transcript-elevenlabs-raw.json"}
}
```

`offset` は推測で書かない。完成MP4の t 秒と、ぼかし映像の t + offset/30 秒を、字幕の掛からない上半分で比べて確かめる。
offset−1・offset・offset+1 の3通りで差を測り、offset だけが明らかに小さいこと（モロッコ編では0.03〜1.1、前後は4〜25）。

以降のスクリプトはすべて作業フォルダで実行する（`uv run SKILL_DIR/scripts/<名前>.py ...`）。

### 2. 候補を選ぶ

本編は2人が動画を止めながら話すので、話している時刻の映像はほとんど止め絵になる。候補を決めたら、同じ場所・同じ話題の**動いている映像**が本編のどこにあるかも探しておく（台本の `video` に使う）。

- 動いている区間は、ぼかし映像を2fps・64×36のグレーにしてフレーム差分（平均1.0超が2秒以上）で探す。中身は2秒ごとのコマ一覧で見当を付ける
- **使う区間は必ず0.25〜0.5秒刻みで本編から抜き出して確かめる**。`fps=1/2` のコマ一覧は表示した時刻と実際の時刻が1〜2秒ずれ、#291 では別の場面（海）が1秒挟まっているのを見落とした
- 本編は同じ短い映像を何度も流し直していることがある（#291 のジュース屋は3回）。同じ映像を2回使わない
- 悪口・注意喚起の字幕（「ぼったくり」「無視しろ」）を、店名の読める看板や、カメラの近くを通る人の上に重ねない。特定の店や人のことだと受け取られる

本編の字幕（`telops-final.json` など）を全部読み、候補を5〜8個挙げる。選ぶ基準:

- **最初の2秒で問いが立つ**: クイズ（「一番人気のジュースは何味？」）、値段（「空港のパンいくら？」）、意外な事実
- **オチで終わる**: 「正解！」「うまいか聞いてんのこっちは」「誰も信じられない国です」のような言い切りやツッコミ
- **映像に見せ場がある**: 砂漠・朝日・名所は、会話が普通でも映像で引ける。ただし話している間は再生を止めていることが多く、映像が止め絵になりやすい
- **単体で通じる**: 前後の話題や画面共有に頼らない

避けるもの: 一般の人の見た目や素性を話す場面（映像が止まっていても話の対象になる）、ネタバレになる公開前の情報、下ネタ。

候補の映像は、本編MP4から8枚程度のコマを並べて確かめる。映像の動きは低解像度のフレーム差分で調べると早い（[references/morocco-290-292.md](references/morocco-290-292.md) に実例）。
ユーザーが選ぶ前に作り込まない。候補とレイアウト案を見せて決めてもらう（モロッコ編では提案した4本がそのまま承認された）。

### 3. 台本（specs/<id>.json）を書く

`words.py <part> <開始秒> <終了秒>` で話者・間ごとの時刻を出し、`--chars` で1文字ずつの時刻を見て切る位置を決める。

```json
{
 "id": "291-juice", "part": "002", "number": "#291", "series": "モロッコ旅行 中編", "bg": "candy",
 "hook": ["モロッコで一番人気の", "ジュースは何味？"],
 "location": {"name": "エッサウィラ", "romanized": "ESSAOUIRA"},
 "segments": [[1063.05, 1067.25], [1068.10, 1071.10]],
 "video": [1711.0, [[2122.25, 2125.5], [2094.0, 0]]],
 "captions": [
  {"at": 1063.05, "s": "m", "lines": ["これが一番人気で", "一番有名"]},
  {"at": 1184.32, "s": "m", "lines": ["正解！"], "big": true}
 ],
 "crops": [{"at": 1063.05, "cx": 930}]
}
```

- **時刻はすべて本編の秒**。`segments` は音声（と映像）の採用区間。1区間の前後に0.05〜0.1秒の余白を取り、隣の語を含めない
- 会話のテンポを優先して詰める。相づち・言い直し・説明の繰り返しを落とし、問い → 掛け合い → オチの順に残す
- **`video`**（省略可）: 映像だけ別の場所から取る。時刻順でなくてよい。`segments` と同じ数の要素で、開始秒だけなら同じ長さ、区間の列なら最後の区間の終わりを自動で合わせる（終わりは0でよい）。話が止め絵の上で進む場面や、映像の見せ場が別の時刻にある回（サハラ）で使う
- **字幕**: 本編の字幕を流用せず、縦型用に書き直す。1行おおむね11文字以内・最大2行。フィラーを除き、話者らしさと疑問・強調は残す。`at` は語の頭の時刻。次の字幕が出るまで表示が続く。`s` は `m`（みちるだ）か `u`（うぱみゅん）
- **`big`**: オチの一言を中央に大きく出す。1本に1〜3回まで
- **話者**: Scribe の話者ラベルは区間によって片方に潰れる（#292の後半）。ラベルを鵜呑みにせず、内容と本編の字幕で決める
- **見出し `hook`**: 最大2行・1行10文字程度。答えやオチは書かず、問いや意外さで引く（「〜は何味？」「〜いくら？」「〜守るべき鉄則」）。マイナスの強い言葉（「ウザい国」）は見出しに使わず、字幕の中に留める
- **`bg`**: 話数 % 4 → 0:lilac / 1:lime / 2:sky / 3:candy。#291 なら candy
- **`crops`**: 正方形レイアウトは元映像の横1080pxを切り出す。`cx` は残す中心の横位置（0〜1920）。場面が変わるたびに被写体へ合わせる。`at` は映像側の時刻（`video` を書いたときはその時刻）。看板などを画面から外すのにも使う
- 長さは本編部分が40〜50秒、最後に「続きは本編で！」が2秒（`tail`）

書いたら素材を切り出す前に検査する:

```bash
uv run SKILL_DIR/scripts/check.py specs/<id>.json   # 字幕の時刻表、✗ 誤り（終了コード1）と ⚠ 警告
```

検査するもの: 形と必須項目、区間の順序と重なり、`video` の長さ、区間の端が語の途中に掛かっていないか、見出しと字幕の文字数、字幕が採用区間の外にないか、読み切れない短さ（0.4秒未満か毎秒12文字超）、`big` の回数、最初の字幕の出だし、`bg` と話数、`crops` の範囲。
⚠ は直すかどうかを判断する。わざと前の語を落として切った所は、語の終わりが次の文字の頭まで伸びているため警告が出ないように余裕を見ているが、出たら `words.py --chars` で確かめる。

### 4. 素材の切り出しと書き出し

```bash
uv run SKILL_DIR/scripts/build_short.py specs/<id>.json --still 300   # 素材を切り出し、静止画で確認
uv run SKILL_DIR/scripts/build_short.py specs/<id>.json --draft       # 半分の解像度で試し書き出し（build/<id>-draft.mp4、40秒ほど）
uv run SKILL_DIR/scripts/build_short.py specs/<id>.json --render      # final/magicalfm-<id>-short.mp4
uv run SKILL_DIR/scripts/build_short.py specs/<id>.json --skip-media --draft   # 字幕だけ直したとき
```

`build_short.py` がやること:

- 区間をフレームに丸めて、ぼかし映像と完成版の音声を切り出す。音声の継ぎ目に12msのフェード
- **焼き込みカードの置き換え**: 録画アプリが元映像に焼き込んだ「ちょっと待って！」カード（左下の水色・橙の帯）が出ているフレームを、直前のカードのないフレームの止め絵に置き換える。カードは一時停止で出るので、止め絵にしても動きは変わらない。置き換えた区間は実行時に表示される
- 最後の「続きは本編で！」の間は、映像の最後のフレームで止める（先を流すと次の場面が映る）
- 音声を −14 LUFS / True Peak −1.5 dB に揃える
- Remotion の AAC は先頭に2048サンプルの遅延が入り、edit list も書かれない。そのぶん前に詰めた `<id>-render.wav` で書き出す
- **止め絵のカットにゆっくり寄る**: 切り出した映像をカット（フレーム差分12超）で分け、3秒以上で7割以上のフレームが止まっているカットを `drifts` として props に入れる。`LiveShort` はそのカットの間に最大10%（短いカットは1秒あたり1.2%まで）寄る。カットの頭で倍率が戻るので、切り替えは目立たない。台本に `"drift": false` と書くと切る
- `build/<id>.props.json` を作り、`--public-dir` に作業フォルダの `public/` を渡して `LiveShort` を書き出す

字幕だけを直すときは `--skip-media` で素材を作り直さない。ただし `segments` や `video` を変えたら必ず素材から作り直す（`--skip-media` のままだと映像・音声とフレームがずれる）。

### 5. 通しの見直しと検査（省略しない）

```bash
uv run SKILL_DIR/scripts/review.py <id> [--draft]                 # 1秒2コマのタイムコードつき一覧（build/review/<id>/sheet_NN.jpg）
uv run SKILL_DIR/scripts/review.py <id> --fps 10 --from 12 --to 14   # 気になる区間を細かく
uv run SKILL_DIR/scripts/verify_short.py <id> [<id> ...]          # 形式・フレーム数・音量・音声のずれ・動きの少ない区間・大きすぎる音
```

- 試し書き出しの段階で `review.py --draft` の一覧を**全部**開き、おかしい所を見つける気で探す: 焼き込みカードの残り、字幕のはみ出し・重なり、`big` の位置、切り抜き位置、ぼかしの状態、一瞬の跳び、間延び。直したら書き出し直し、本番の書き出し後にもう一度見る
- `verify_short.py`: 1080×1920・30fps、フレーム数が props と一致、−14±1 LUFS、True Peak ≤ −1 dB、音声のずれが3か所とも0ms
- `lowMotion`（映像の変化が6秒以上小さい区間。3つ目の値は寄りが掛かっているか）は離脱の原因になる。寄りは保険で、まず `video` で動いている映像を別の時刻から取る（サハラの方法）。モロッコ編の会話の3本は、最初の版では後半25〜34秒がほぼ止め絵だった
- `loudSpots`（3秒平均が −11 LUFS 超）が出たら、笑い声や叫びが大きすぎないか聞いて確かめる
- **顔ぼかしは人以外にも掛かっている**ことがある。#292 ではラクダの顔の寄りが大きくぼかされていたので、その映像を使わず別の場面に差し替えた
- カードを置き換えた区間は前後のコマを並べて、帯の切れ端が残っていないか見る

### 6. 引き渡し

- `final/` の MP4 の絶対パス、長さ、音量、選んだ理由（問いとオチ）を報告する
- 顔ぼかしは本編の処理を引き継いでいるだけで、ショートで使った区間を人が全部見たわけではない。その旨を伝える
- 投稿は別依頼。YouTube Shorts / Reels へ上げるときは `post-clip`（R2 アップロードと `clips.json` が前提）に従う

## レイアウト

`LiveShort` の `layout`:

| 値 | 内容 |
| --- | --- |
| `square`（既定） | 中央に横1080×縦1030の映像。元の解像度のまま切り出すので画質が落ちない。見出しは上、字幕は映像の下側に重ねる |
| `full` | 映像を縦いっぱいに広げる。1.8倍に拡大するので少しぼやける |
| `band` | 横長の映像を丸ごと見せ、上下を番組色の帯にする |

モロッコ編では3案を静止画で並べて見せ、`square` で作った。Shorts の画面は上約170px・下約400px・右約140pxがUIに隠れるので、見出しと字幕はその内側に置く。

## スキルを育てる

ユーザーの感想で直したことのうち、次のショートでも効くもの（字幕の長さ、切り方、映像の選び方、音量など）は、その1本だけ直して終わらせない。
`check.py` の警告、`LiveShort.tsx` の部品、この SKILL.md の基準のどれかに入れる。一度きりの演出のために大きな仕組みは足さない。
`LiveShort.tsx` の描画はフレーム番号だけで決める（CSS アニメーション・`Math.random`・`Date.now` を使わない）。
